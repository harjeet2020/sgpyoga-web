# SGP Yoga Website Warp Instructions

## Introduction
This is a yoga studio website built using HTML, CSS and JavaScript. It is a responsive website that is optimized for mobile devices and search engines.

## Site Information

### Basic Information
The yoga studio name is SGP Yoga. It is located in CDMX, Mexico. We offer in-person classes and events in various venues around the city.

### Site Structure
The site is structured into the following pages:
- Home (index.html)
- About (about.html)
- Classes (classes.html)
- Events (events.html)
- Blog (`/blog/` and `/es/blog/`, built by Eleventy from `blog/src/`). Each post's URL comes from the `slug` in its front matter: lowercase-kebab-case, in the post's own language, validated at build time. Changing a published slug needs a 301 in `netlify.toml`. The blog used to live at `/blog/dist/`; the redirects from there are in `netlify.toml`.

### The site uses the following colors:
Primary Color: #1f2121 (Eerie Black)
Secondary Color: #ffeddf (Linen)
Accent Color 1: #40689a (Lapis Lazuli)
Accent Color 2: #905d7b (Chinese Violet; darkened from #a06789 in Sept 2026 for WCAG AA contrast)
Supplemetary Color: #3e3e3e (Onyx)

### The site uses the following fonts:
Heading Font: Cormorant Garamond
Body Font: Lato Light

### Languages
- The site supports English and Spanish languages
- Language is selected automatically based on user's browser language, falling back to English (default)
- There is a dropdown menu in the navbar for manual language selection
- We're using i18next library to implement multiple language support
- We store translations in JSON files under the locales folder
- All html tags use data-i18n attribute to fetch translations

## Guidelines
- Use the provided color palette and fonts
- Use images found under the assets folder
- Use icons from lucide.dev icon library, **as inline SVG** (see "Icons, fonts and third-party scripts" below)
- Save current progress and project info upon request under memory-bank folder
- Create / update documentation upon request under docs folder
- Use reusable CSS classes to achieve clean and maintainable code
- Use CSS variables for colors and fonts
- Structure CSS files in a readable & maintainable way, using comments to explain the purpose of each section
- Ensure all html tags use data-i18n attribute to fetch translations
- When using images, provide both high and low resolution versions to ensure optimal performance
- Use absolute paths (starting with `/`) for all asset references in HTML files (e.g., `/assets/...`, `/css/...`, `/js/...`) to ensure the Spanish build works correctly

## Generated content: the class schedule and events

The weekly schedule, the class-type legend and the events are **not hand-written**. Staff edit them in the platform's admin panel (`platform.sgpyoga.co/admin/school`), they are stored in Supabase, and `npm run build:content` (the first step of `npm run build`, source in `scripts/content/`) bakes them into static files at build time. The site never talks to Supabase from the browser.

**Never hand-edit these generated files.** They are gitignored and overwritten on every build:
- `classes.html`: rendered from `templates/classes.html`. Edit the template instead; its `BUILD:` markers must stay, each exactly once.
- `events.html`: rendered from `templates/events.html`, with every event card baked in at the `BUILD:events-cards` marker and the events' schema.org JSON-LD at `BUILD:events-schema`. Same rule: edit the template.
- `.build/jsonld/`: structured data for the Spanish pages (for example `events.es.json`), which `build-i18n.js` swaps into any `<script type="application/ld+json" data-jsonld="NAME">`.
- `js/eventsData.js`: rendered from `templates/eventsData.js`, where the helper functions live.
- `css/schedule-colours.css`
- `locales/{en,es}/schedule.json` and `locales/{en,es}/eventContent.json`: generated translation namespaces. Never copy their keys into an authored file such as `classes.json` or `events.json`.
- `assets/photos/school/`: teacher and event images downloaded from Supabase Storage.
- `es/`: the Spanish pages, generated by `build-i18n.js`.

The event cards are static HTML rendered by `scripts/content/eventCards.js`, so `js/events.js` never builds a card: it filters, switches between upcoming and past, and fills the modal by hiding, reordering and reading the cards already on the page. Each card's text carries `data-i18n="eventContent:<id>.<field>"`, which `build-i18n.js` and `js/i18n.js` both resolve against the generated namespace directly. The events' structured data is rendered at build time too, by `scripts/content/eventSchema.js` (see `docs/EVENT-STRUCTURED-DATA.md`). It replaced the browser script `js/eventSchema.js`, which has been deleted. That script was the last runtime reader of `js/eventsData.js` and of the `events:events.<id>.*` graft in `js/i18n.js` (`composeGeneratedNamespaces`). Both are still generated and kept exactly as they are until C2 in `MIGRATION.md` is revisited.

**Building locally** needs Supabase credentials in a gitignored `.env` (copy `.env.example`). Point it at the local stack (`npm run db:start` in `platform/`) or at the hosted project; both are read-only. Then run `npm run build` and serve `_site/` with `python3 -m http.server`. The content build fails loudly, naming the cause, if Supabase is unreachable, returns an empty schedule or event list, or holds a `<` in any text. That is deliberate: on Netlify a failed build leaves the previous deploy live, while a "successful" empty one would publish a blank timetable.

## Icons, fonts and third-party scripts

These rules keep the pages fast (see the Sept 2026 SEO & speed pass). Please don't undo them by accident.

- **Icons are inline SVG. There is no Lucide script.** The site used to load the whole Lucide library (660 KB) from a CDN to draw about 15 icons. To add an icon, copy its SVG from lucide.dev into the HTML with the attributes the existing icons use (`class="lucide lucide-<name> <your-classes>"`, `aria-hidden="true"`, 24×24 viewBox, `stroke="currentColor"`). Markup generated by `scripts/content/` gets icons from `scripts/content/icons.js`. Never write `<i data-lucide>`: nothing converts it any more. Don't put an icon inside an element with `data-i18n`, because translating in place replaces the element's text and would delete it.
- **No CDN scripts.** i18next, its language detector and Fuse.js are pinned, self-hosted copies in `js/vendor/` (see its README for versions and how to upgrade). Unversioned CDN URLs cost a redirect on every page load.
- **Fonts are WOFF2 subsets** (`*.woff2` next to each `*.ttf`, which stays as the fallback). They cover Latin, Latin Extended, Vietnamese, punctuation and currency. If content ever needs another script (for example Cyrillic), regenerate the subsets with fontTools:
  `pyftsubset Font.ttf --unicodes="U+0000-024F,U+02B0-02FF,U+0300-036F,U+1E00-1EFF,U+2000-206F,U+20A0-20CF,U+2100-214F,U+2190-21FF,U+2200-22FF,U+FB00-FB06,U+FEFF,U+FFFD,<new ranges>" --layout-features='*' --flavor=woff2 --output-file=Font.woff2`
- **Preloads must match what CSS loads**: font preloads point at the `.woff2` files with `type="font/woff2"`.
- **Images:** encode WebP at quality 92 (the site's standard) and set `sizes` to the real rendered width, so retina screens get the right file and nothing larger. Keep a high-resolution original of anything you re-encode in `assets-src/originals/`, which is never deployed.
- **Redirects live in `netlify.toml`** and need `force = true`, or Netlify serves a matching file first and the rule never fires. `www` goes to the apex domain in one hop. Use `https://sgpyoga.co` (never `www.`) in canonical tags, hreflang, sitemap and structured data.

## SEO tags on the Spanish pages

- `<meta>` tags are void elements, so they're translated with `data-i18n-content="namespace:key"` (the build replaces the `content` attribute). Plain `data-i18n` only works on elements with a closing tag.
- Every page's meta description, `og:description` and `twitter:description` use `<page-namespace>:meta.description`, and `og:title`/`twitter:title` use `common:pageTitles.<page>`. A new page needs those keys in both languages.
- `build-i18n.js` also rewrites canonical, hreflang, `og:url`/`twitter:url` and `og:locale` for `/es/`. The homepage's canonical URL is `https://sgpyoga.co/` (not `/index.html`).
- After changing anything SEO-related, run `npm run build` and then `npm run validate`.
